## J integration contract

Add `{"registration", DawarichWeb.AuthRegistration.Http}` to AuthGate. Pass
`enabled: true` and a `context` map with `self_hosted`, `oidc` and
`registration_enabled`. Defaults resolve the native registration authority and
treat unset `SELF_HOSTED` as self-hosted. Authority failure denies signup.
Registration owns GET `/users/sign_up` and POST `/users`.

Pass `native: true` to credentials, recovery, AuthRestore, account updates,
API-key rotation, OTP and browser two-factor handlers in standalone mode.
Credentials also need the existing boolean `registration_enabled` option and
`otp_enabled` option. Old coexistence admission/hand-back remains when native
mode is absent. Recovery adds PATCH `/users/password` and POST `_method=patch`.
For API two-factor, set `conn.assigns.api_native = true` through J's API pipeline.

Wire `DawarichWeb.AuthAccount.Destroy` for DELETE `/users` and GET
`/users/me/destroy/confirm`, and `DawarichWeb.Api.AccountDestroyController` for
DELETE `/api/v1/users/me`. Preserve the source pending-payment guard exemption
on API account destruction. The controller uses the existing `api_user` and
`api_params` assigns and `Api.Respond` response seam.

Resolve POST `/users` method override dispatch before choosing a handler.
Registration and account update currently both claim this POST path; deletion
must reach the destruction handler after `_method=delete` normalization.
Do not route an account update form into registration. Native options apply to
J's standalone handler calls, not just the feature-key lists.

## Native behavior supplied

Credentials retain wrong/blank-password counters, lock creation, unlock delivery
intents, Trackable IP selection through RailsRemoteIp, OIDC-only password denial,
Warden cookies and session rotation. Unknown users run the existing dummy hash.
Bodies are bounded before credential effects; CSRF/origin checks precede writes.

Recovery accepts PUT/PATCH reset, enforces the six-hour expiry boundary, locks
the token row, clears reset/password/OTP locks, sanitizes settings and writes
compatible Warden cookies. Reset and unlock delivery use the existing native
`Dawarich.Auth.Recovery.MailWorker.enqueue/1` seam.

Registration validates normalized email/password confirmation, handles duplicate
email races, creates API keys, activates self-hosted pro users for 1,000 calendar
years, preserves locale and accepts matching invitations when registration is
disabled. OIDC-only source policy denies signup before the invitation exemption.
Invitation acceptance locks family/invitation rows, creates membership and both
member/owner notifications through the native notification-event producer.

Cloud signup retains pending-payment status, reverse-trial checkout JWT, gads,
UTM, Partnero and signup-intent state through explicit callback seams. Pending
import claims call the package E implementation. Server PostHog is excluded by
ruling 6; retained attribution callbacks are not retired.

Remember restoration writes Warden/Trackable; signout clears the all-device
remember timestamp. Browser OTP preserves four invalid-code forms, fifth-failure
navigation, the account lock threshold and one-hour lock-email throttle. Native
browser two-factor management uses row locks and compatible encrypted secrets,
backup-code consumption and CSRF validation. API availability precedes password
checking and writes run in a row-locking transaction.

Account changes validate current password without a login/Trackable side effect,
allow the OAuth source exemption and replace password salts. API-key rotation
invalidates the old key and its rate-limit cache entry. Account destruction guards
family owners, uses purpose-bound signed tokens, source-compatible Redis consumed
markers and a native deletion enqueue callback. Missing owners produce native
errors before a tombstone. Confirmation does not sign out a different user.

Nil/false session and CSRF keys are regenerated. Session cookies preserve Rails
protocols and flags; overflow remains an explicit error.

## Native owner dependencies

MAIL must complete the native recovery SMTP transport. Cloud signup context
needs `callbacks.webhook(user_id)`, optional `callbacks.partnero(user_id, referral)`
and `callbacks.accept_invitation(user_id, invitation_id)` for Cloud invitations;
each callback returns `:ok` on accepted native work. Missing required owners
return 503 and cannot authorize route activation. Webhook/Partnero transport is
locally stubbed in package tests.

OTP context needs `enqueue_otp_lock(user)` returning `:ok`. Account-destruction
context needs `enqueue_destroy(user_id)` and, for Cloud,
`enqueue_confirmation(payload)`. The latter receives user ID, locale, link URL,
SHA-256 of the link token and expiry. Provide it through the
`:account_destroy_context` application setting or browser handler context.
Native deletion worker and confirmation/lock-notification variants are A12f-3
owner dependencies; F does not create a Sidekiq producer for them.

Package E claim ownership must be native before activating signup ticket claims.
J also owns the mobile completion handoff where required; F does not replace H's
callback or add a cycle between packages.

## Client IP trust contract (2026-10-07 security correction)

`DawarichWeb.RailsRemoteIp.ip/1` is the shared client identity for rate limits,
credential sign-in, remember-token restoration, OTP, account linking, recovery,
Apple/OAuth providers and trial welcome tracking. Socket addresses remain raw in
`RailsProxy.Headers.request/1` so delegated Rails requests retain their original
peer and forwarding chain.

The accepted IP headers are `X-Forwarded-For` and `Client-IP`. RFC 7239
`Forwarded` and `X-Real-IP` do not supply client identity. The ingress proxy must
overwrite, not append, client-supplied XFF and Client-IP at the public boundary,
or strip the unused family. Internal proxy chains may then append verified hops;
changing a supplied prefix cannot override the rightmost non-proxy address.
If ingress writes neither identity family, it must strip both. The app's actual
Rails RemoteIp configuration also accepts unsanitized pass-through identities;
Phoenix preserves that defect under [DRB-036](deferred-rails-bugs.md#reverse-proxy-identity-security).

Selection follows ActionDispatch::RemoteIp: discard invalid addresses, reverse
XFF then Client-IP, remove trusted proxies, and fall back to the furthest supplied
address or socket peer. Client-IP validation accepts bracketed IPv6 and full
host masks (/32, /128 or an all-ones address mask), preserves the supplied text,
and rejects non-host masks. Proxy matching parses those accepted forms;
spoof checking compares the original Client-IP text with parsed XFF values,
so differently spelled equivalent addresses still conflict, as in Rails.
Conflicting Client-IP/XFF raises IpSpoofAttackError;
the limiter returns 500 before charging any bucket. The default proxy ranges
match Rails, including IPv4/IPv6 link-local addresses. Application configuration
`:dawarich, :trusted_proxies` accepts IP/CIDR strings; a nonempty list replaces
the defaults, while an absent or empty list retains them.

Rails 8.1.3.1 with Rack 3.2.7 actually inherits RFC Forwarded precedence in
`Request#forwarded_for`. Rails' existing Rack::Attack rules also use `req.ip`.
Ignoring RFC Forwarded here is the controller's explicit security correction
for an XFF-writing ingress that passes client Forwarded headers through, rather
than preservation of that installed Rails/Rack weakness. Host/scheme parsing
continues through RequestURL, RackScheme and HostAuthorization.

Regression coverage: `rails_remote_ip_test.exs` checks filtering, spoof refusal
and proxy replacement; `trial_welcome_endpoint_test.exs` proves shared unlock
and OAuth challenge attempt six is 429 in both modes with rotating Forwarded,
XFF prefixes and X-Real-IP under production host authorization. The pass-through
regression characterizes Rails' fresh budgets on both routes in both modes when
ingress writes neither identity family, including the accepted Client-IP forms.
