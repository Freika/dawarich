## Deferred stage browser mutations

The written `v2/map/video-export.spec.js` journey exercises the real native hook/encoder/upload/gallery against an explicit synthetic horizontal source snapshot. It uses the documented source injection contract, keeps overview camera, disables the marker, and selects a magenta route to isolate route pixels from map and HUD colors. Its 1.4-second and 3.8-second frames are both before the three-second summary outro. Known start and middle image regions must progress, and expected DAY 01 / 01 and DISTANCE glyph masks must match decoded frames with compression-tolerant contrast. The MP4 major brand must be `isom`.

The controller executes these mutations individually at the approved stage browser gate, restoring after each:

- `freeze-replay-route`: replace the frame-loop fraction with constant `0.08`; expect "route must reach the known middle segment".
- `remove-replay-route`: supply empty features to both route sources in `moveTrack`; expect "route must include the known starting segment".
- `omit-replay-hud`: replace the frame-loop HUD import with a no-op local function; expect "decoded day HUD must match its expected glyphs" (or the distance glyph assertion).

These browser mutations are written handoffs, not executed browser evidence. Node helper tests run the pixel classifier on synthetic RGBA images and reject frozen/full-from-start/missing route metrics and missing HUD matches. Mutations removing the progression and HUD verification guards fail their corresponding Node tests. The browser thresholds, codec decoding and font masks still require the controller's approved real-browser run.
