# Native frontend architecture context

Status: **DRAFT implementation context**, 2026-10-10. Accepted direction: ADR-0017; final cleanup and acceptance are pending. The historical [frontend contexts plan](native-frontend-contexts-plan-20261008.md) remains unchanged. [Inventory](native-m7-inventory.md) and [reader/case mapping](native-m7-test-retargets.md) are the code-coupled handoff.

Phoenix owns native documents, page state/forms/events and local refusals. Contexts take `Accounts.Scope`, refresh admission before effects, and own validation/transactions/durable jobs/publication. Hooks wrap browser libraries rather than domain commands or a Stimulus registry. Pure browser library state is keyed and bounded; async/server deliveries reject stale tokens and recheck authorization. Credential forms and public capabilities follow the existing secret-state/log rules.

Feature ownership remains: accounts/auth HTTP (3c), Places list (3d), imports/exports/notifications/family/sharing commands (4), data/editor/trips/achievements (5), maps/replay/poster/video/onboarding/Areas and public/family map hosts (6). Milestone 7 owns shared bridge/envelope/asset/routing cleanup and reader reconciliation. B4a–B4c group surviving web files into `features/<feature>` in small path batches, keeping module names, neighboring templates, URLs and Scope interfaces. A4 owns browser library grouping. These directories are a target, not a claim that the current tree was moved.

Direct router groups retain auth/session/CSRF, host/SSL/body/rate/origin, malformed-input, owner/privacy/expiry and operator checks. B1 already promotes the secondary standalone APIs on m7; B2 extracts full-document `.html`/`format=html` aliases and replaces frame/minimal-layout/ownership handbacks; B3 then retires per-request proxies/slices/macros. A correct refusal reaches its safe destination once. Native requests never use Rails as a missing-route/error fallback after cleanup. Separate Rails whole-app startup is the approved fallback strategy, with X4 packaging/startup compatibility evidence still pending.

Names such as RailsCookies, RailsSession, signed Active Storage, ActionText stored content and ActionCable do not justify removal. Keep encryption/session/data/download/API and proven external wire contracts. The native UI has no Turbo consumer at completion; unknown independently deployed Cable consumers remain explicitly unresolved and retained pending OD4. Preserve operational readiness/lifecycle/source-debt seams. Cloud native admission stays fail-closed on all validated preconditions (Cloud configuration, direct session DB URL for leases and HTTPS Manager/canonical hosts); native Cloud must not become the default. This documentation changes no guard or deployment default.

The native JS esbuild path exists today; native CSS/fonts/images and mixed Docker/build-input discovery still depend on Rails asset inputs. [Development instructions](native-frontend-development.md) distinguish that current state from A3/A4's proposed native digest manifest/data-export split. Positive renderer/font/worker/geodata/Swagger/PWA coverage must precede payload deletion.

S1 owner attestations, final month/trip/shared-month hosts, 4/6 family hook reconciliation, A/B cleanup, C1 assertion splits, C2 E2E and X4/X5 acceptance remain. Performance D1–D4 is removed by the controller's scope cut; existing functional and byte-boundary tests remain. No full suite, browser gate, production image/serving or 390px acceptance is claimed by this draft.
