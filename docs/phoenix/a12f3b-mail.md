# A12f-3b MAIL producer contracts

Last updated: 2026-10-07. Scope: plan C M01–M12. This package supplies native mail producer seams and preserves retained source contracts subject to the recorded differences; it does not activate Cloud routing, flip owners, or certify source retirement.

## Producer interfaces

- `Dawarich.Mail.DeviseCallbacks.update/4` saves a validated email/password hash and native notification intents together. `after_update/3` returns accepted jobs for callers that already own the credential transaction; call `after_commit/1` only after that transaction commits. An SMTP failure after commit leaves the credential saved, returns a delivery failure, and retains a retryable intent. `update/4` defers synchronous delivery when called within an existing transaction. CLI email/password changes use this seam. Production Cloud sends email-change notifications to the old address and password-change notifications to the resulting address. Unchanged values, skip flags, and self-hosted mode suppress them. Password validation/hashing, registration, session changes, API validation, and account lifecycle stay with the authentication owner.
- `Dawarich.Mail.UserCallbacks.created/3` runs inside the creator's transaction after the user and trial effects exist. Cloud trial creation produces welcome immediately and explore-features two days later; self-hosted and `skip_auto_trial` suppress both. Both command owners must be native. Locked user lookup and outbox dedupe preserve the first accepted event and schedule across replay, including dispatched rows. The caller owns trial creation and webhook effects.
- `Dawarich.Mail.UserCallbacks.link/5` accepts the authentication owner's already-issued OAuth-link or destruction-confirmation URL. It preserves URL, token expiry, provider label and SHA-256 digest in a typed command. Existing workers verify the accepted URL against its digest; queued args omit the raw URL. Signing and account deletion remain separate authentication responsibilities.
- `Dawarich.Auth.Otp.Lockout.register_failed_attempt/3` commits source-compatible failed-attempt/lock accounting before the cache throttle and mail enqueue. Ten attempts lock for thirty minutes; an expired lock restarts accounting. The one-hour throttle uses the Rails-compatible cache entry, not a new SQL timestamp column. Enqueue or SMTP failure does not undo the lock or clear the throttle. The authentication owner must call it from the native invalid-OTP path.

## Delivery and retry behavior

Explicit Reply-To is retained for multipart and HTML-only SMTP. Reset/unlock delivery uses the current recipient locale and original raw token while keeping only the digest in recovery state. Credential notification content retains the source callback's old/new recipient snapshot and locale.

Delivery attempts acquire the shared SQL heartbeat lease before claiming or sending. A concurrent inline or queued executor snoozes; successful replay sees the durable receipt. The active attempt refreshes `claimed_at`; immutable `issued_at` is backfilled from existing claims by `20261007180000_separate_mail_issuance_time.exs`. Receipts are fenced by the current lease holder, and a lost claim returns an error. Family-lapse delivery uses the same lease around its transactional marker and send. Workers must run outside enclosing transactions so the heartbeat can renew on another connection.

Archival retry retains its first issuance time and deterministic subscription JTI, so the accepted event's upgrade URL and Message-ID remain stable after rejection. Once the accepted link reaches its thirty-minute expiry, the worker cancels without SMTP or a delivery receipt. Rails generates a fresh token on render; cancellation is the explicit stable-identity policy permitted by the review brief. Family-lapse retry reuses its initial claim key even though Rails clears the user warning flag on SMTP failure. Delivery receipts are written after transport acceptance. SMTP cannot provide exactly-once receipt across an acceptance/receipt-write crash.

Test-email admission accepts the transport's existing STARTTLS, SSL and plain/login/CRAM-MD5 authentication configuration, plus XOAUTH2 in standalone mode. Retained Rails test mail is HTML-only without a test MIME header; the Cloud HTTP endpoint rejects the action and self-hosted delivery queues it. The ADMIN owner consumes the existing `TestEmail.run/4` interface. The action, producer and worker now require an admin. An endpoint guard refuses authenticated non-admin POSTs with 403 before any Rails handoff, including pinned routes. The worker reloads current admin status so demotion after enqueue cancels delivery. Each accepted POST receives a distinct UUID; legacy queued jobs use a deterministic identity from their durable Oban job ID. Successful job redelivery sends nothing. These are explicit review-authorized differences from Rails (ED-MAIL-TEST-ADMIN and ED-MAIL-TEST-REDELIVERY).

### Native SMTP authentication boundary

The configured AUTH mechanism is forced by `Dawarich.Mail.SmtpAuthentication` and `SmtpTransport`. This supersedes the sole-mechanism refusal in AFFiNE ADR `uV80V1dHKCmjQqcbsHbjW`; see [configured SMTP transport decision](adr-configured-smtp-transport.md), shared AFFiNE document `5ylweLA5CBHVWv_eGnC0J`.

Rails `lib/smtp_config.rb` accepts seven authentication names. Locked Mail 2.9.1/net-smtp 0.5.1 implements PLAIN, LOGIN, CRAM-MD5 and XOAUTH2; DIGEST-MD5, GSSAPI and NTLM require authenticator extensions and otherwise fail.

| `SMTP_AUTHENTICATION` | Rails with the locked gems | Native Phoenix |
| --- | --- | --- |
| absent, blank, `plain` | Forces PLAIN | Forces PLAIN |
| `login` | Forces LOGIN | Forces LOGIN |
| `cram_md5` | Forces CRAM-MD5 | Forces CRAM-MD5 |
| `xoauth2` | Forces XOAUTH2; password contains the bearer credential | Forces XOAUTH2 |
| `digest_md5`, `gssapi`, `ntlm` | Runtime rejects without an authenticator extension | Refuses before connection |
| `none`, `nil`, `false`, `off`, `disabled` | Disables AUTH and drops credentials | Disables AUTH and drops credentials |

The authenticated transport uses gen_smtp's public `smtp_socket` API for connection/TLS and existing MIME encoding. It implements the SMTP session explicitly because gen_smtp_client cannot select one configured authenticator and otherwise falls through to another mechanism after rejection. Server advertisement order, multiple mechanisms and absence of AUTH advertisement do not change the configured selection, matching net-smtp. Rejected AUTH or malformed challenges terminate before MAIL; no other authenticator or unauthenticated delivery is attempted. Transport errors retain status classifications without returning server text that might echo credentials. Authentication commands, credentials and tokens are never logged. Unauthenticated delivery retains gen_smtp_client.

`SMTP_SSL=true` (or port 465 without an SSL override) uses implicit TLS. Otherwise STARTTLS defaults to required; an explicit value other than literal `true` disables it. Missing STARTTLS or failed required TLS cannot fall back to plaintext. After STARTTLS the client repeats EHLO before AUTH. Certificate verification defaults to peer with hostname checking; `SMTP_OPENSSL_VERIFY_MODE=none` is an explicit operator override. Both protocols use the same certificate options; `SMTP_CA_FILE` supplies the trust file, otherwise system roots apply. Every session runs in a short-lived task and closes its sockets. The E2E sink refuses explicit or credential-implied AUTH and explicit SSL/STARTTLS requirements.

XOAUTH2 remains Rails-owned for recovery/test-email admission during coexistence; `DAWARICH_RAILS=off` admits it through the shared configuration seam. No route envelopes, status/body/redirect/flash or job semantics changed. Cloud lifecycle remains refused in every mode pending external L1 handoff.

`smtp_policy_test.exs` covers each mechanism against local ephemeral servers advertising multiple orders, a single mechanism and no AUTH methods. It checks exact credential encoding, immediate and challenge-stage rejection without fallback, unsupported names, sink policy and unavailable required STARTTLS. `smtp_tls_review_test.exs` verifies all four authenticators over both verified implicit TLS and STARTTLS, rejecting hostname mismatch before AUTH, alongside existing certificate trust/timeout coverage. The implementation report records RED, GREEN and one isolated production mutation per new named test.

Location commands continue accepting the existing two-field payload and additionally accept an explicit ambient locale. Native workers use current target preferences first, then the accepted fallback locale. Owner OFF emits only a reverse command; owner ON emits only the forward intent. FAMILY owns request validation and cache-NX producer accounting.

Digest child events are deterministic from period and parent event. They differ from the calculation event and keep the first locale, timezone, due time and payload after dispatch/replay. Preserve [DRB-013](deferred-rails-bugs.md): digest `sent_at` is set after enqueue, before SMTP acceptance; a validation failure after enqueue can leave mail queued. This package does not change that Rails bug.

## Dormant source debt

`Dawarich.Jobs.Drain.status/2` optionally accepts `source_status:` from retained Rails `JobDrain.status`, with observed queued/scheduled/retry/dead/busy/unknown counts. Unknown/nonzero wrapper debt blocks forward and binary rollback gates; an unreadable snapshot also blocks them. This interface never deserializes Ruby arguments or GlobalIDs. Native typed workers discard their own missing recipients without a delivery receipt.

The controller must supply the retained-source census to the operational gate. An absent optional snapshot preserves native SQL status with `scope: native_sql`, `g49: BLOCKED` and source inspection required, and a private synthetic empty queue is not evidence for source retirement. Under master ruling 9, confirmation, member-joined and the four no-op trial APIs/templates may be removed only after retained wrappers are inventoried and disposed. The merged Phoenix port includes the later retirement decisions and `UserCallbacks.enqueue/4`; MAIL retains its `created/3` and `link/5` producer interfaces alongside that API.
