# Visual parity baseline: Rails 1.16.0 vs Phoenix (2026-10-19)

Plan: `superpowers/plans/2026-10-18-phoenix-rails-visual-map-parity-plan.md`, task B2.

## Bench

- **Apps and data.** Rails `freikin/dawarich:1.16.0` and Phoenix (`fix/map-realtime-parity` image, standalone) share one database seeded with the E2E demo data: 17 988 points, 118 tracks, 1 trip, 148 visits. Phoenix has its own Redis. The bench is in the E2E repo, branch `feat/parity-bench`, under `scripts/parity/`.
- **Capture** (`capture.mjs`):
  - the database is restored from a snapshot before each app pass;
  - the theme is switched through `users.theme`;
  - for each route it saves the raw server HTML and full-page screenshots at 1440×900 and 390×844, light and dark;
  - it checks horizontal scroll at 390 px in `en` and `de`.
- **Report** (`report.mjs`):
  - the DOM is the normalized `<body>` (`ParityHTML` with the ADR-0025 wiring allowlist);
  - pixels are compared with `pixelmatch` (threshold 0.1) over viewport-high slices, and the worst slice is reported;
  - a page-size difference (↕) fails.
- **Repeatability.** Rerunning the settings family gave the same percentages for unchanged pages, so the bench is deterministic for static pages.

## Findings

1. **Shared chrome sets a floor of about 0.8 % on every page.**
   - Rails wraps pages in a centred container and ends them with a footer ("Dawarich 2023–2026").
   - Phoenix pages run full width and have no footer.
   - Fixing the layout first (D1) should remove the small diffs on imports, exports, tags, notifications and settings.
2. **`/map` differs in layout.** Rails renders a left icon rail, a date bar and a floating panel over the map. Phoenix stacks its controls above the map (C1/C2). Other map observations:
   - Both apps load the basemap from the same host.
   - Rails issues about 800 requests while loading `/map` and Phoenix about 94. The initial-load comparison belongs to B3.
3. **Behaviour mismatches, not just markup:**
   - `/family` without a family: Rails redirects to `/family/new`, while Phoenix renders an empty family page with status 200.
   - `GET /users/password/new` signed out: Rails renders the form, while Phoenix answers 422 with a plain "Invalid recovery request". This is a bug for D6.
4. **Rails pages that scroll sideways at 390 px:** `/trips/:id`, `/imports/:id` and `/settings/background_jobs`, in both `en` and `de`. Phoenix does not. Under the text-resilience rule these become `resilience` entries in the register rather than being copied.
5. **Biggest gaps:** map, trip page, achievements, stats month and insights, where Phoenix renders 1 700+ extra DOM lines.
