  and GET /users/auth/failure. GET initiation returns native 404.
  Configuration retains the source deployment-mode split.
- `DawarichWeb.AuthAccountLink.Http`, enabled: true, **closure: true**,
  for GET /auth/account_link, GET/POST /auth/account_link/challenge,

  Omitting closure retains the earlier A11e coexistence contract; J must

  rollback switches and real Endpoint integration. These tests call handlers
  directly and do not claim those Endpoint routes.

Both handlers take `context:` as their existing application integration seam.
Use real implementations for `enqueue_link.(payload) -> :ok`,
`callbacks.webhook.(user_id) -> :ok`,
`callbacks.partnero.(user_id, referral) -> :ok` and
`mobile_redirect.(user, client_type) -> {:ok, local_path}`.
The mail payload matches the existing version-1
mail.user.oauth_account_link worker: user_id, locale, provider_label, link_url,
link_token_sha256 and link_expires_at. Do not log the URL or payload.
Absent required mail/signup/mobile owners fail natively; no Rails replay occurs.

Shared contracts for H:

- `Google.verify_id_token(token, context)` returns `{:ok, string_keyed_claims}`
  or `{:error, :invalid_credentials}`. Context supports env, audiences, nonce,
  clock and jwks_uri. An absent/empty mobile nonce remains optional.
- `Accounts.resolve(identity, context)` returns `{:ok, user, created?}`,
  `{:ok, nil, false}`, `{:link_required, details}` or `{:error, reason}`.
  Identity fields are provider, uid, email, email_verified, first_name,
  last_name. Normalize provider verification using H's source contract.
  Link details include user, provider, uid, rate_limited and retry_after.
  Web uses raise_only; send_email retains source send throttling.
- `Completion.run(conn, provider, exchange, context)` calls exchange exactly
  once, resolves the account, and owns all terminal completion/failure effects.
  `Completion.complete/5` accepts an already resolved account.

The native sign-in cookie uses F's SessionCookie/AuthCookie wire contract.
OAuth signs in OTP-enabled accounts directly, as Rails does. Token/password
linkage instead links only for OTP-enabled users and requires later sign-in.
Pending import claim uses E's existing Claim service before redirect.
Returning accounts do not receive signup attribution or creation webhooks.
OAuth-created accounts retain a NULL signup_variant; password registration
bucketing does not apply. Locked accounts do not receive a login cookie.
Token consumption precedes identity save and is retained on subsequent failure.

## Review fixes and J activation requirements

The retained Google web strategy uses userinfo only when its ID token is
absent or empty. A present token rejected for audience, expiry, issuer, nonce,
signature or decoding now returns invalid credentials. Completion cannot
create an account, issue a linkage challenge or log in after that rejection.
The shared Google verifier checks optional `nbf` with the source strategy's
60-second leeway; optional mobile nonce policy remains unchanged.
Default Google consent scopes match `userinfo.email,userinfo.profile` after
the retained strategy expands both Google API URLs; no `openid` is added.

Provider HTTP now admits the source `client` parameter and stores only `ios`
or `android`, selecting the header before the parameter. Completion also
handles a header directly, and selects the header before the stored client.
An unrecognized header cannot cause parameter/session mobile fallback, matching
Rails. Invitation and payment destinations still precede mobile completion.
`Completion.client_session/2` is the normalization seam; J must retain it
by dispatching through the provider handler rather than bypassing that handler.

Before activation, J must verify all of the review's transport/owner requirements:

- Dispatch provider initiation through the POST, authenticity-token and
  same-origin checks. Retain signed/encrypted sessions, native duplicate-cookie
  refusal and callback state consumption before completion.
- Wire real mail, signup webhook, Partnero and H mobile owners. Select
  account-link `closure: true` and `closure_route?/1`. Missing required owners
  remain terminal native failures; never replay after exchange, DB or mail effects.
- Preserve allowed mobile header/parameter propagation on initiation and
  callback, including header precedence and invitation/payment priority.
  A wired mobile callback alone is insufficient.
- Own canonical paths, HEAD, formats, malformed/duplicate cookies and rate/body
  admission at the real Endpoint. Direct-handler tests do not prove activation.
- Keep current OIDC nonce override/missing-ID-token and PKCE policies, and
  optional Google mobile nonce. H's shared Google verifier now refuses future
  not-before claims outside the source leeway.
- Preserve signature/algorithm/issuer/audience/expiry checks and bounded JWKS
  refresh. Tests cover key rotation, not every signing/cache configuration.
- Require explicit linkage for verified email collisions, retain SQL uniqueness,
  atomic consumed-token markers and redemption row locks. Different-email race
  schedules and consumed-marker coexistence still need broader characterization.
- Preserve F's fresh login session, local return/mobile destination validation and
  native pending-import ownership. Never accept an external mobile destination.
- Keep diagnostics redacted: no provider tokens, exchange/profile bodies,
  account-link URLs or payloads in logs or error reporting. Completion telemetry
  carries a fixed reason only.
