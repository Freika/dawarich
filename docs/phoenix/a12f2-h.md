## J wiring contract

- Dispatch POST `/api/v1/auth/{login,otp_challenge,register,google,apple}` (including `.json`) to `DawarichWeb.AuthMobile.Http.call(conn, enabled: true, context: context)`. Its `route?/1` selects these routes. `AuthApi.Http.call/2` delegates to it when `standalone: true` or native standalone mode is enabled; the existing coexistence behavior remains available.
- Dispatch GET `/users/auth/apple` and POST `/users/auth/apple/callback` to `DawarichWeb.AuthApple.Http.call/2` with `enabled: true`. Exempt only the callback from the browser CSRF check: its state and nonce are validated using the encrypted cookies. Preserve the common host, SSL and rate-limit policies.
- Dispatch GET/HEAD `/auth/ios/success` to `DawarichWeb.AuthMobile.Success.call/2`.
- Dispatch POST `/api/v1/subscriptions/callback` to `DawarichWeb.Api.SubscriptionsController.call/2`, excluding ordinary API authentication and pending-payment gates.
- Supply F/G's browser `mobile_redirect` context callback as `fn user, client -> Dawarich.Auth.Mobile.Handoff.redirect(user, client, context) end`. F/G retain invitation and pending-payment priority before invoking that callback. Common browser transport retains the query/header client marker.
- Reuse the existing native producer callbacks: `enqueue_link`, `enqueue_otp_lock`, `callbacks.webhook` and `callbacks.accept_invitation`. The API handlers do not issue Warden, remember or browser Trackable effects. Callback failure after account creation is terminal; it must not re-enter Rails.

## Security and retained source policy

Apple and Google mobile requests verify signed ID tokens before resolving an account. Apple reuses G's JWKS implementation and key rotation, restricts signatures to RS256, and checks Apple issuer, configured audience, expiry, not-before and nonempty subject. Invalid tokens have no userinfo fallback. Apple compares the SHA256 nonce claim when the caller supplies a nonce; absent nonce remains optional under NE-5 and controller ruling 12. Web callbacks use the web services audience and decrypted nonce cookie. Configuration follows `01_constants.rb:75` and `VerifyAppleToken`.

Apple state and nonce use encrypted Rails cookie purposes, ten-minute expiry, Secure, HttpOnly and SameSite=None. The pending import ticket uses the same cross-site cookie bridge. Callbacks delete these cookies before account resolution and restore the ticket to the native session. Retained browser state cookies have Rails' client-side one-time semantics; this port does not add a separate server-side replay protocol.

Mobile password login keeps constant-cost dummy bcrypt work for absent accounts, respects the explicit OIDC/password policy, and leaves web counters/cookies unchanged. OTP uses F's token family, cache coder, backup consumption and partial-save ordering, with native refusal responses and source failure counters. OAuth email collisions use G's verification-email flow and never disclose the existing account's API key.

The mobile handoff token carries only `api_key` and a five-minute `exp`, signed with `AUTH_JWT_SECRET_KEY` or the Rails-secret fallback. The success route renders the source localized plain body when a token is present and JSON with the root URL otherwise.

Subscription callbacks retain webhook-secret validation, HS256 JWT verification, required expiration, seven-day Rails-cache NX event markers, source watermark keys and integer encoding, older/equal/zero timestamp behavior, a user lock with watermark recheck, rollback marker release and committed-event retention. Unknown plans are ignored with a diagnostic. Cloud plan/state changes produce existing family commands in the outbox. No Manager request is made.
