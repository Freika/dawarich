# Milestone 7 incremental test and reader mapping

Status: incremental C1 handoff, 2026-10-10. C1 retirement/acceptance remains pending. This mapping authorizes no production or fixture deletion.

The [case ledger](native-m7-test-retargets.json) maps the inventory's 254 historical test/support entries and 392 reader entries: 549 distinct files, 2,578 named case definitions and 127 relevant ED/FRB/DRB rows. Four readers exist only on a feature head and are included from that head. The ledger deliberately includes unaffected data/security readers so their retention is explicit. It supplements [inventory Appendices B/F](native-m7-inventory.md), rather than replacing the historical census.

## How to use the ledger

`pins` identifies immutable committed trees read from stage1, m4, m5, m6 and the m7 base. No uncommitted sibling changes are evidence. m4 advanced from the earlier inventory pin to `70443b32f5cec3e359e475797216f5633e36a231`; its updated reader/case definitions are included here. At final recheck m6 advanced to `ffd317a2270e4ff1596a5d55f207e5f5b9bfe91a`; the map format/navigation/readiness changes were inspected from that committed tree and the mapping refreshed. `map_document` adds four exact native alias/grant/retired-format successors for PageEnvelope/auth readers. Branch source presence is evidence of a named successor, not a green test or S1 attestation.

Each `files` entry carries the exact old file and case name, classification, named successor, feature contract, cleanup successor, and retained fixture policy. A successor with `head/file/name` exists at the recorded head. A successor with `contract/cleanup` names the existing cases in `feature_contracts` **and** the still-planned A/B test in `planned_cleanup_successors`. These are separate obligations: the feature cases protect user behavior, while A/B proves removal of the shared mechanism. Those rows give no retirement clearance until the changed assertions are split and both obligations pass on the integrated branch.

The 2,441 exact retained cases keep their existing named reader; 29 renamed feature cases have exact successor names; 106 cases require the feature-contract cases plus the planned shared-cleanup successor; two patch cases are retargeted here. B means behavior/data/security, M means markup/mechanism, C means coexistence. Mixed cases retain B assertions and effects. Classification is conservative: a legacy word in a title does not make an assertion removable. Body/crypto/API/wire bytes remain valid oracles.

Dynamic names such as `#{page["name"]}` and `#{@name}` are the exact test-definition templates. Their existing fixture selectors/generators and entire corpus remain retained; the ledger does not invent expanded names or pin externally owned fixture bytes. `reader` carries literal corpus names from F10. A helper/emitter/setup file has `named_callers` or a named feature contract, not a fictitious standalone test. Shared helpers stay under `test/support` and must compile in every partition.

`register_rows` associates every selected register ID with its existing readers and named feature/cleanup contracts. Historical rows stay; later A/B differences explicitly supersede them after behavior evidence. No ED, FRB or DRB was added or removed by this mapping. Generic register readers remain mandatory even for rows selected through dynamic helpers.
