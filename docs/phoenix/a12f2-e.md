## Source quirks, producer and failure boundaries

Uploads save SQL/blob attachment metadata before the storage callback, then enqueue processing after successful storage. A storage error retains the committed row/attachment but no processing command; a later render error retains the processing command. Rejected/rolled-back intake does not write a storage object. The trial limit remains five non-demo imports and 11 MiB; extension validation is case insensitive. File names preserve the user's local second, including the source same-second collision: a third same-name intake can fail validation. Claim collision likewise rolls back its ticket. Report this preserved bug to the controller-owned deferred Rails bugs document.

Pending intake reserves the exact UTC-day cache key for two days, refuses over 10 GiB and releases that original key on failure. Accepted tickets expire after 24 hours and link to the serving host's signup endpoint. SQL/storage failure can leave an unclaimed pending row while the reservation returns to zero. Local storage staging copies are removed after success/failure. No new exactly-once HTTP guarantee is introduced.

Point writes physically delete actor-owned rows and adjust actor/import counters. Relocation permits only coordinates, clears reverse-geocoding state as Rails does, determines countries with `ST_Contains`, and retains tile, achievement, geocoding and track producer payloads. Position writes lock the track before the point, compare both revisions, recalculate the native track/segments, return canonical 409 state, retain minute-precision/history time-zone parsing and publish the composite map-edit event after commit. Generic track publication is suppressed for this operation. Anomaly acceptance preserves the Rails boolean cache wire/30-minute flag and creates one reset command; date/range parameters are ignored by the source action.

Ingestion closes the characterized scalar/container/device/region casts, dates and native source 422/500 results. Dimension SQL casts remain distinct from legacy point-column casts: boolean device IDs store `t/f` in point columns and `true/false` in the source dimension, and the source array-device SQL quirk is retained. Raw JSON and live payloads preserve their original values; normal-import parsing remains separate. A failed second 1000-row slice retains the accepted first slice, as Rails does, and never replays it upstream.

Existing import/anomaly/track/geocoding command ownership is locked when producing outbox work. Sidekiq-owned keys retain the existing reverse-command payload; Oban-owned keys use existing native workers. Remaining reverse-effect consumers for tile epochs, achievements, stats, live broadcasts and destroy follow-up are A12f-3 activation dependencies. No worker/SMTP/scheduler retirement, browser closure, image/stand rehearsal or Ruby-free release acceptance is asserted. Rollback must pin new work to Rails and drain accepted native work to zero; no native-to-Sidekiq transfer.

Retain separate transport/admission compatibility rows until J's Endpoint proof. No deliberate semantic change is proposed, and the remaining Needs-Eugene recommendations follow controller rulings 12–13 (Rails parity).
