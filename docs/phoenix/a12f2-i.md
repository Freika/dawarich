## Contracts and source authority

Installed activestorage 8.1.3.1 is the oracle: blobs/proxy_controller.rb:14, concerns/active_storage/streaming.rb:16, representations/base_controller.rb:13, models/active_storage/variation.rb:35, variant_with_record.rb:43 and blob/representable.rb:176. config/application.rb:22–24 selects the disabled processor. No attachment declares a source image variant, but valid signed transformations and persisted image variants remain supported. NullTransformer returns original bytes; resize, rotation, quality and requested output format do not transform the image. The requested format still determines representation proxy headers, while the stored blob uses identified image content type for the redirect. Records use the source Ruby Marshal SHA1 variation digest, including key order, symbols and default format.

NE-2 retains image variants. Its PDF/video recommendation only considers retirement after usage/product review; it supplies no unconditional retirement. PDF and video previews therefore remain native, using the source pdftoppm and ffmpeg arguments and persisted preview_image attachment. These executables remain required in the release image (A12f-4 ownership), with no new Mix dependency.

Blob proxy preserves public signed-ID access, serving MIME/disposition restrictions, bounded local/S3 streaming, single/suffix/multipart ranges, 416s, immutable cache validators, HEAD and provider failures. S3 whole streams preserve the SDK's two HEADs followed by 5 MiB GET ranges, including the unclamped final range; HEAD also reads the object. The first chunk is read before committing headers, so initial GET failures return a terminal source 500; ranges follow source count and aggregate-size limits. File paths and filenames use the existing storage safety and disposition helpers.

Direct uploads admit guests with valid Rails session CSRF, including the legacy unmasked real token and masked real/global forms. The read-only shared CSRF helper is supplemented inside the owned handler. JSON, URL-encoded and multipart bodies and streamed/chunked bodies use the same blob creation boundary. Existing disk checksum/type/length validation, rename and temporary cleanup remain. Missing required upload attributes and null sizes preserve source 500s; negative sizes, scalar string/integer casts and dropped non-hash metadata preserve source successes. Source-compatible ordered JSON includes signed IDs and local/S3 upload targets. A rejected CSRF request inserts no blob; an error after accepted blob creation is terminal and retains that blob.

A variant SQL failure before commit rolls back rows; a failure after storage upload preserves one reusable variant/blob/file. Partial streaming failures terminate the committed response. These handlers have no Rails replay branch. Native keys, attachments and variation digests remain readable by Rails on the same database; no Sidekiq transfer is introduced.
